# 5단계 상세 개발계획

## 1단계 — 데이터·공급자 기반 (상용화 게이트)

목표: 표본을 실시간 비교로 바꿀 수 있는 최소 상용 구조. 공급자 계약 전에는 adapter fixture만 실행한다.

작업: 공급자 키 Secret 등록, HotelOfferV1 매핑, 검색 요청 검증, timeout/retry/circuit-breaker, 총액·환율 원장, `dataStatus`·`collectedAt`·`sourceUrl`, P0 테스트, 상태 배너.

완료조건: 동일 입력 20회 중 schema 100%, 세금 포함 여부 누락 0건, 공급자 장애 fixture에서 안전한 부분 결과, 비로그인/로그인 저장 경계 통과.

## 2단계 — 비교·전환

작업: 공급자 2곳 병합, 동일 객실 dedupe, 판매처 카드, deep link/subId, 클릭아웃 실패 복귀, 제휴 고지, 결과→상세→외부 이동 분석.

완료조건: 파트너 URL allowlist 100%, 오픈 리다이렉트 0건, 클릭아웃 이벤트와 고지 문구가 일치, 모바일/PC 키보드 흐름 통과.

## 3단계 — 신뢰·재방문

작업: 리뷰 출처·수집시각, 지도 또는 지역 설명, 저장 검색, 가격 알림, 철회·삭제·만료, 유연한 날짜·지역 대안, 다국어·통화.

완료조건: 모든 외부 데이터에 출처와 시각, 알림 동의 철회 1분 내 반영, 통화/반올림 contract test 100%, 지도 실패에도 핵심 과업 가능.

## 4단계 — 운영·품질

작업: SLO·대시보드·온콜, 공급자별 모니터링, 합성 사용자·접근성·성능·보안 회귀, Android 유휴 1대 QR/PWA/오프라인, 장애 사후 보고 템플릿.

완료조건: 7일 합성 모니터링, 핵심 Web Vitals 목표, WCAG 핵심 흐름, 복구 drill, 증거 링크.

## 5단계 — 차별화·수익

작업: 총액 신뢰 지수, 설명 가능한 추천, 회원 혜택, 가격 이력, 콘텐츠·광고 슬롯(승인 후), 제휴 정산 리포트.

완료조건: 실데이터 30일, 사용자 동의, 추천 설명 A/B에서 과장 표현 0건, 수익 이벤트와 환불/취소 조정.

## 단계 운영 규칙

각 단계는 이전 단계의 증거가 PASS일 때만 열린다. 공급자·광고·법률·Android가 막히면 해당 부분을 `WAITING_EXTERNAL`로 기록하고 내부 문서·fixture·테스트를 먼저 완성한다. 100%는 “코드 작성량”이 아니라 단계별 증거 충족으로만 선언한다.
