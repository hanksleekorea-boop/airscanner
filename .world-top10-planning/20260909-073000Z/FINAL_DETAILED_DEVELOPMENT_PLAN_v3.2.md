# HotelScanner 최종 통합 상세개발계획서 v3.2

상태: **계획서 작성 완료 / 실제 상용화 개발은 미완료**

이 문서는 기존 HotelScanner 계획, Cloudflare·OAuth·D1 구현 기록, 세계 톱10 비교, 갭 원장, v3.2 X10 분석을 하나로 합친 실행 정본이다. 계획된 기능을 구현 완료로 표시하지 않는다.

## 0. 현재 기준선

- 공개 서비스: `https://hotelscanner.scanners.cc/`
- 현황판: `https://hotelscanner.scanners.cc/dashboard/`
- 현재 데이터: `SAMPLE_ONLY`, 외부 공급자 수 0
- 내부 기반: Cloudflare Worker, D1, WeSaver Google OAuth, PWA, 계정 내보내기·삭제
- 실제 미완료: OTA 공급자, 제휴 클릭아웃, 실시간 총액, 지도, 가격 알림, 법률·광고, Android
- 범위 제외: B드라이브, Apple 로그인, 결제, 직접 예약·발권

## 1. 개발 규칙

1. 외부 키가 없으면 실제 API 호출 대신 고정 fixture를 사용한다.
2. 모든 가격은 `currency`, `baseAmount`, `taxAmount`, `feeAmount`, `totalAmount`, `collectedAt`, `dataStatus`, `sourceUrl`을 가진다.
3. 모르는 값은 0으로 바꾸지 않고 `null + unknownReason`으로 표시한다.
4. 공급자 장애는 전체 검색 장애가 아니라 부분 결과·재시도·대체 경로로 표현한다.
5. 계획·fixture·자동시험은 실제 예약·실제 사용자·실기기 증거로 간주하지 않는다.
6. 각 단계 종료 전 이전 단계의 시험과 증거를 다시 확인한다.

## 2. 단계별 개발 명세

### 1단계 — 실시간 데이터 기반과 무료 상용화 게이트

목표: 표본 검색을 계약된 공급자 가격 비교로 전환한다.

작업:

1. 공급자 계약·국가·통화·쿼터·허용 용도 확인.
2. Cloudflare Secret에 키 등록; 저장소와 채팅에는 값 기록 금지.
3. 정상·매진·세금 누락·timeout·429 fixture 작성.
4. 공급자 응답을 `HotelOfferV1`로 정규화.
5. 객실·숙박일·인원·취소 정책 fingerprint 생성.
6. 총액·세금·수수료·환율 원장 구현.
7. `collectedAt`, stale 여부, 원문 URL 표시.
8. timeout·retry·backoff·circuit breaker 구현.
9. 공급자별 상태를 `OK/PARTIAL/TIMEOUT/RATE_LIMITED/INVALID/STALE`로 표시.
10. 표본과 실시간 결과를 색·문구·상태값으로 분리.

인수조건:

- 5종 fixture의 schema 검증 100%.
- 세금·수수료 누락을 숨기는 결과 0건.
- 공급자 timeout/429/5xx에서 안전한 부분 결과.
- 비로그인 검색과 OAuth 계정 저장 경계 통과.
- 실제 공급자 계약·키·쿼터 증거가 없으면 단계는 `BLOCKED_EXTERNAL`.

### 2단계 — 판매처 비교와 클릭아웃

목표: 사용자가 조건이 같은 판매처를 비교하고 승인된 판매처로 이동한다.

작업:

1. 두 공급자 결과 병합.
2. 동일 숙소·객실 중복 제거.
3. 판매처별 가격·취소·조식·결제시점 카드.
4. 서버 allowlist 기반 deep link 생성.
5. 익명 `subId` 추적값 생성.
6. 쿠키·제휴 고지와 동의 상태 처리.
7. 외부 이동 실패 시 검색 결과로 복귀.
8. 클릭아웃 성공·실패·차단 이벤트 기록.

인수조건:

- 허용되지 않은 외부 URL 이동 0건.
- open redirect 0건.
- `subId`에 개인정보 0건.
- 실패 클릭아웃의 복귀율 100% fixture.
- 제휴·쿠키 고지에 대한 법률 승인 증거.

### 3단계 — 신뢰·재방문 기능

목표: 가격 숫자뿐 아니라 선택 근거와 재방문 가치를 제공한다.

작업:

1. 리뷰 출처·수집시각·리뷰 수 표시.
2. 지도 또는 거리·지역 리스트 대체 기능.
3. 저장 검색과 삭제 기능.
4. 가격 임계값 알림.
5. 알림 동의·철회·만료·실패 상태.
6. 날짜 ±1일·인접 지역·숙소 유형 대안.
7. 한국어·원화·영어 fallback.
8. 통화별 소수점·반올림 규칙.

인수조건:

- 모든 외부 자료에 출처·시각 표시.
- 알림 철회가 1분 내 반영.
- 지도 장애에도 핵심 검색·비교 가능.
- 통화·날짜 contract test 100%.
- 사용자 데이터 내보내기·삭제 확인.

### 4단계 — 운영·품질·실기기

목표: 지속 운영 가능한 서비스 품질을 확보한다.

작업:

1. 가용성 99.5%, 검색 p95 2초 목표 설정.
2. 공급자별 오류·쿼터·stale 모니터링.
3. 장애 배너·대체 공급자·마지막 정상 결과 처리.
4. 운영 담당자·온콜·지원 이메일 지정.
5. WCAG 핵심 흐름 점검.
6. 느린 연결·오프라인·여러 탭·세션 만료 시험.
7. 화면이 꺼진 유휴 Android 1대에서 QR·PWA·오프라인 검증.
8. 장애 사후 보고와 복구 훈련.

인수조건:

- 7일 합성 모니터링 증거.
- 핵심 접근성 흐름 통과.
- Android QR→PWA→오프라인→재연결 증거.
- 장애 복구 drill 통과.
- SLO 담당자와 연락처 확인.

### 5단계 — 차별화·수익 확장

목표: 실데이터에 기반한 신뢰·추천·수익 기능을 추가한다.

작업:

1. 총액 신뢰지수.
2. 설명 가능한 추천.
3. 가격 이력.
4. 회원 혜택.
5. 승인된 광고 슬롯.
6. 제휴 정산 보고.
7. 콘텐츠·지역 가이드.

인수조건:

- 실데이터 30일 이상.
- 추천 근거와 사용자 제어 제공.
- 광고·제휴·쿠키 법률 승인.
- 취소·환불·정산 조정 가능.
- 최저가 보장처럼 오해시키는 문구 0건.

## 3. 작업카드 작성 형식

모든 작업카드는 다음 10개 핵심 칸을 반드시 가진다: 목적, 입력, 담당, 선행조건, 정상 절차, 실패 절차, 경계 조건, 보안·개인정보, 시험, 완료 증거. v3.2의 64필드 목표는 아직 미달이며, 실제 계약·운영 값이 생길 때 확장한다.

## 4. 외부 행동과 AI 단독 작업

AI 단독 가능: fixture, schema 검증, 총액 계산, 장애 시험, URL allowlist, 상태 UI, 접근성 자동 점검, 로그 마스킹, 합성 사용자 시험, 문서·증거 생성.

사람 필요: 공급자 계약·키, 제휴 정산, 법률·광고 승인, 운영 책임자, 실제 Android 연결, 결제·직접 예약 범위 결정.

## 5. 공개 전 최종 게이트

다음 중 하나라도 남으면 공개 문구는 `SAMPLE_ONLY` 또는 `WAITING_EXTERNAL`이어야 한다: 실시간 공급자 미확인, 총액 원장 미검증, 클릭아웃 고지 미승인, 법률 검토 미완료, 운영 담당자 미지정, Android 증거 미확인.

## 6. 최종 판정

이 계획서는 저숙련 AI가 순서대로 실행할 수 있는 상세 명세로 완성됐다. 그러나 계획서 완성과 실제 제품 개발 완료는 다르다. 현재 제품의 전체 상용화 완료율은 100%가 아니며, 1단계 외부 공급자 게이트가 해소되기 전에는 실시간 최저가 서비스로 공개하면 안 된다.
